1. PROJECT OVERVIEW
-------------------
Rootory is a mobile-friendly growing workspace for farmers and home gardeners,
built for Bit N Build — Track 3: Jan Jeevan.
Tech Stack:
- Frontend: Next.js 16.3.5 (Turbopack), React 19, TypeScript, Lucide React, Radix Dialog, Custom CSS Tokens (No Tailwind/shadcn).
- Local State & PWA: idb (IndexedDB), Service Worker, offline-first app shell.
- Backend & DB: Supabase (PostgreSQL, Auth, Storage, RLS).
- AI & External APIs: @google/genai (Gemini 3.6 Flash), Open-Meteo (Live Weather), Sharp (Server-side image re-encoding & EXIF scrubbing).


2. ALL BACKEND MIGRATIONS & CURRENT STATE
-----------------------------------------
The database has evolved across 5 migrations located in `supabase/migrations/`:

- 001_private_gardens.sql:
  * Private garden backup table with atomic revision check.
  * Private bucket for plant images with owner-only access.
  * Auth configured for 6-digit email codes (via {{ .Token }} in Supabase template).

- 002_account_gardens.sql:
  * Materializes relational tables: profiles, plants, plant_updates, reminders, health_observations.
  * 700ms debounced automatic saving with serialized revision queue.
  * Server-side assessment quota table (`assessment_usage`) and Postgres function `claim_plant_assessment()`.
  * Note: The AI quota limit is customized for demo/testing:
    - Default accounts: 10 AI assessments per UTC hour.
    - Demo Account (`demo@rootory.example`): 500 AI assessments per UTC hour via `claim_plant_assessment()`.

- 003_community.sql:
  * Public community posts, comments, likes, and bookmarks.
  * `community-images` public storage bucket.
  * Logic handled in `lib/community.ts` and synced with local IndexedDB.

- 004_marketplace.sql (Uncommitted / Staged):
  * `marketplace_listings`: Public read, authenticated owner write/delete. Price validation.
  * `enquiries`: Participant-only read (sender and seller).
  * PostgreSQL trigger `route_enquiry()`: Validates listing availability, sets seller_id, ensures sender_id matches auth.uid(), fetches sender profile name.
  * Sync logic implemented in `lib/marketplace.ts`.

- 005_crop_safety.sql (Uncommitted / Staged):
  * `grower_locations`: Private latitude/longitude/locality for growers.
  * `crop_reports`: Growers submit pest/disease observations.
  * `alerts`: Targeted in-app alerts table.
  * PostgreSQL function `review_crop_report(report uuid, approve boolean)`:
    - Restricted to admins (`is_rootory_admin()`).
    - Reports must be < 7 days old.
    - Calculates distance: dispatches alerts to growers of the SAME crop within 10 km!
  * `admin_members` table and `moderate_content()` function for taking down posts/listings.


3. KEY FRONTEND & COMPONENT CHANGES

- `components/rootory.tsx`:

  * `storage.ts` now tracks `marketplaceVersion: 1` alongside `communityVersion: 1`.

- `app/api/plant-health/route.ts`:
  * Rate limited via `claim_plant_assessment()` in Postgres.
  * Re-encodes uploaded images server-side using `sharp` (strips EXIF metadata, resizes to 1200x1200px max, 80% JPEG).
  * Model set to `gemini-3.6-flash`.
  * Returns structured JSON matching `assessmentSchema`.
